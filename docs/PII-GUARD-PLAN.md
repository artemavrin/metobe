# Защита данных: план встраивания PII Guard

2026-11-16. Перед каждым вызовом внешней модели Metobe прячет персональные данные (имена, телефоны, почту, документы, адреса, счета), а в ответе возвращает настоящие значения. Человек может открыть у любого ответа, что именно ушло в модель. Шлюз — наш форк PII Guard (`~/dev/ai/pii-guard`, ветка `ru-pack`): русский слой «один человек — одна метка, имя в нужном падеже» и дообученная русская NER ru-s34 (среднее весов ru-v3 и ru-v4, 2026-11-17).

Шаги названы буквой З. Пометки как в `MEMORY-PLAN.md`:

- **Допущение** — выбрано мной по умолчанию, можно пересмотреть до начала шага.
- **Проверить** — по коду не установлено, выясняется первым действием шага.

Размер: S — до дня, M — 1–2 дня, L — 3+ дня, оценка без замеров. Общие правила — `MEMORY-PLAN.md` §0 (прогоны через Gateway с ценой заранее, тесты рядом, миграции сразу на `purr`, спорный экран — через прототип).

## 1. Что есть сейчас

**Metobe.**

- Каждый вызов модели получает её через одну функцию: `getLanguageModel` / `getEvaluationModel` (`packages/core/src/ai.ts:63,72`). Вызовов 12: чат, итоговый проход, название, сжатие, описание картинки, запись памяти, решения памяти, сводка карточки, черновик напоминания, периодические задачи, правка задачи, Telegram. Эмбеддингов нет.
- Middleware AI SDK (`wrapLanguageModel`) нигде не используется — место свободно.
- Результаты тулов сторонних данных: MCP (через обёртку `tool-sources.ts`), почта, веб, вложения, память. В чате есть `prepareStep` на каждый шаг; в задачах и Telegram его нет.
- Точный запрос к модели нигде не хранится, функции «что ушло в модель» нет. `model_runs` хранит только токены и цену.
- `zeroDataRetention` передаётся только в памяти, напоминаниях, сводке и Telegram.

**PII Guard.**

- OpenAI-совместимый шлюз (`/v1/chat/completions`, `/v1/responses`, `/v1/messages`) с потоком, маскированием аргументов и результатов тулов, повторной проверкой перед отправкой. Русский слой подключён только сюда.
- REST `/v1/mask`, `/v1/unmask`, `/v1/analyze` — без русского слоя (`routes/mask.py:134`).
- Метка — `HMAC(ключ, сессия, тип, значение)`: одно и то же значение в одной сессии всегда даёт одну метку, поэтому кэш промптов у провайдера не ломается.
- Хранилище меток и реестр людей — в памяти одного процесса, TTL сессии час. Списка «метка → тип → значение» шлюз наружу не отдаёт; echo показывает замаскированный текст.
- Один провайдер наверху на развёртывание (или «проекты» с эндпоинтом на провайдера).

## 2. Как встраивать — главное решение (D46)

### Вариант А. Шлюз как источник

В Metobe заводится источник `openai-compatible` с адресом шлюза, шлюз ходит к провайдеру.

- Плюс: ноль кода в Metobe, вся логика шлюза (тулы, поток, проверка) уже готова.
- Минус: Metobe говорит с моделью только как с chat completions. Теряются особенности провайдеров, которыми мы пользуемся: Responses API у OpenAI, кэш промптов Anthropic, `providerOptions.gateway` (в том числе `zeroDataRetention`), Yandex со своим `fetch`. Под каждый источник нужен свой эндпоинт шлюза с копией ключа. Показать «что ушло» можно только из echo, без списка меток.

### Вариант Б. Middleware в Metobe, шлюз как служба маскирования (рекомендую)

`getLanguageModel` оборачивает модель в `wrapLanguageModel` с нашим middleware:

1. `transformParams`: собрать из промпта куски текста (сообщения, аргументы и результаты тулов, instructions, блок `<memory>`), отправить одним запросом в шлюз, подставить замаскированные.
2. `wrapStream` / `wrapGenerate`: восстановить текст ответа и аргументы вызовов тулов **до** того, как AI SDK выполнит тул, — тул получает настоящие значения.
3. Записать, что ушло, к сообщению (§5).

- Плюс: работает с любым источником и не трогает провайдерские настройки; одна точка на все 12 вызовов; Metobe сам решает, что маскировать (настройки §6), и сам хранит запись для UI.
- Минус: в форке нужен новый метод «замаскировать набор кусков» с русским слоем и восстановление в потоке (§3). Логику шлюза для JSON в результатах тулов переиспользуем, а не переписываем.

**Решено владельцем (2026-11-16): вариант Б.**

## 4. Шаги

### З0. Spike S19

Цель — убедиться, что вариант Б работает до вложений в форк.

- Middleware в AI SDK текущей версии: `transformParams` видит весь промпт, `wrapStream` может править `tool-call` до выполнения тула (**Проверить** по `node_modules/ai`, память об API устарела).
- Пробный прогон: русский диалог с тулом почты на Muse Ember через Gateway. Метки `Персона_Женщина_…` модель переносит в аргументы тула и в ответ; имя возвращается в нужном падеже. Цена заранее, около $0,1.
- Задержка: маскирование истории из 20 сообщений и восстановление потока — цель не больше +100 мс к первому токену на CPU.

Готово, когда: прогон проходит без утечек, тул получает настоящий адрес, задержка измерена.

**Сделано (2026-11-17).** `apps/cli/dev/pii-guard-check.ts` через рабочий путь `getLanguageModel`, Muse Ember, шлюз с ru-s34: в модель не ушло ни одного исходного значения, тул отправки получил настоящие адреса, ответ восстановлен в падежах («Ответил Ольге… Копию поставил Илье Кузнецову»), «Смирнова»/«Ольга» и «Кузнецов»/«Илья Кузнецов» — по одной метке. Маскирование на CPU — 120–420 мс на шаг: цель «+100 мс» не достигнута, первый шаг дороже (вся история).

### З1. Форк PII Guard

- Новый метод `POST /v1/mask/segments`: `{session_id, language, segments: [{id, kind: text|json, value}]}` → `{segments: [{id, masked}], entities: [{placeholder, type, value, segment_id, start, end}]}`. Внутри — тот же путь, что `Gateway.mask` (русский слой, JSON в результатах тулов, повторная проверка).
- `POST /v1/unmask` с `LabelSession` (имена в падеже) и потоковый вариант: Metobe шлёт хвосты текста, шлюз держит незаконченную метку (`hold_from`) и отдаёт готовое.
- Образ шлюза — отдельный, см. «Образ и сервис» ниже.
- **Сделано (2026-11-17), форк `317cc31`:** метод в виде `POST /s/<сессия>/v1/chat/mask` (тело chat completions целиком, а не куски — тот же путь, что у шлюза) и `/chat/restore` (`text`, `arguments`, `stream` с хвостом `held`); тесты `tests/gateway/test_metobe_routes.py`. Образ — не сделан.
- **Допущение:** значения в ответе `entities` отдаём — Metobe и так хранит исходный текст, а без них не нарисовать «показать оригинал». Шлюз доступен только из сети Metobe.

**Образ и сервис.** Metobe раздаётся одним `compose.yml` (образ `ghcr.io/artemavrin/metobe`, необязательные части — профилями `db`, `s3`, `updater`). Шлюз — ещё один сервис со своим образом:

- `ghcr.io/artemavrin/pii-guard` из форка: `Dockerfile.metobe` с NER (torch на CPU, transformers), extra `ru` (pymorphy3, словари, pytrovich), `PII_GUARD_DEFAULT_LANGUAGE=ru`. **Сделано (2026-11-17):** форк — приватный `artemavrin/pii-guard` (ветка `main` = `ru-pack`); образ собирает его workflow `metobe-image.yml` на машинах GitHub под linux/amd64 и linux/arm64 при каждом изменении кода в `main`, теги `ru-s34` (его закрепляет `compose.yml` Metobe) и `sha-…`. Пакет публичный, репозиторий — нет: установки Metobe скачивают образ без входа. Workflow основного проекта в форке выключены.
- Веса NER (ru-s34, 1 ГБ) — внутри образа: работает без интернета, версия модели = версия образа, образ около 2,4 ГБ. В git весов нет: workflow берёт их из релиза `model-ru-s34` форка и сверяет sha256. Новая модель — новый релиз `model-<имя>` и смена `MODEL` в workflow.
- Сервис `pii-guard` в `compose.yml`: порт только во внутренней сети compose, наружу не публикуется; `PII_GUARD_TENANT_KEY` и токен Metobe → шлюз генерирует `metobe.sh` при установке, как остальные секреты (**Проверить** по `metobe.sh`). Память около 2 ГБ (**Проверить**).
- Профиль `pii`: без него сервис не стартует и раздел «Защита данных» показывает «не установлено» — установки без защиты не тянут лишние 3 ГБ (**Допущение**).
- **Сделано (2026-11-18), 0.10.1:** службу включает переключатель «Маскировать данные». Приложение просит обновлятель через Redis (`metobe:guard:*`). Обновлятель:
  - дописывает ключ и токен;
  - включает профиль `pii` и скачивает образ;
  - поднимает службу и ждёт, пока загрузится модель;
  - только после этого ставит `privacy.bundled`: до этого вызовы идут как раньше, а не блокируются;
  - если у приложения нет токена (старый `.env`), пересоздаёт его, дождавшись дописанных ответов.

  Выключение останавливает службу и убирает профиль. Ключ и токен старым установкам дописывают и `install.sh`, и обновлятель: при запуске и при каждом обновлении. Без обновлятеля службу включает `METOBE_PII=1` у `install.sh`, он же пишет `PII_GUARD_URL`. Если свободной памяти меньше 2 ГБ, раздел предупреждает до включения. `PII_GUARD_ALLOWED_HOSTS: pii-guard` обязателен: без него служба отвечает приложению 400 `Invalid host header` (так было в 0.10.0).

- **Сделано (2026-11-18), 0.10.2: длинные чаты на слабом сервере.** На сервере с 2 ядрами чат на 870 тыс. символов (результаты MCP из 1С) не маскировался за 30 с ни разу. Причины:
  - разбор бросался вместе с запросом;
  - сессия неудачного первого запроса удалялась вместе со своим кэшем;
  - каждый повтор начинал ту же работу заново, и очередь росла, пока по таймауту не начали падать и короткие запросы.

  В форке (`e962855`) разбор после таймаута доходит до конца и кладёт результат в кэш, сессия на это время сохраняется, а повтор ждёт уже идущий разбор. Запросы без таймаута работают как раньше. `compose.yml` закрепляет образ по коммиту (`sha-…`): тег `ru-s34` переезжает при каждой сборке, и уже установленные серверы по нему новый образ не скачают. Очередь памяти, пока защита недоступна, ждёт 5 минут: попытка не засчитывается, сообщение не теряется, проверка «стоит ли запоминать» не глотает ошибку.

- В `docker/compose.dev.yml` тот же сервис для разработки.

### З2. Middleware и служба

**Сделано (2026-11-17), без службы в compose:** `packages/core/src/pii-guard.ts` (сборка тела из промпта AI SDK, тексты и рассуждения, вызовы и результаты тулов; восстановление ответа без потока, в потоке с хвостами на каждую часть, аргументов тула до его запуска; без запроса к шлюзу, если в куске нет даже начала метки), `getLanguageModel(…, { session, onMasked })`. Пока нет раздела настроек (З6), защита включается адресом `PII_GUARD_URL` (+ `PII_GUARD_TOKEN`) для всех внешних источников; локальные не трогаются. Сессия — чат, задача (`task-<id>`), чат Telegram; остальные вызовы — своя сессия на вызов. Шлюз недоступен — модель не вызывается, в чате код `guard-unavailable`. Модели решений (`getEvaluationModel`) пока не маскируются — З3.

- `packages/core/src/pii-guard.ts`: клиент, сборка кусков из промпта AI SDK, подстановка, восстановление потока.
- `getLanguageModel(sourceId, modelId, { purpose, chatId })` оборачивает модель, если защита включена для этого назначения (§6). Сессия шлюза — `chatId` (для задачи — `taskId`, для памяти — запись очереди).
- Локальные источники (`sources.local = true`) не маскируются по умолчанию: данные не уходят.
- Шлюз недоступен: для внешних источников запрос не уходит, человек видит сухую ошибку «Защита данных недоступна: запрос не отправлен» (решение владельца).
- Служба в compose рядом с web и worker, один процесс; хранилище в памяти. После рестарта метки те же (HMAC), реестр людей пересобирается при следующем маскировании истории (**Проверить**).

### З3. Покрытие вызовов

| Вызов | Что маскируем | Особенность |
| --- | --- | --- |
| Чат, итоговый проход | всё | основной случай |
| Периодические задачи, правка задачи | всё | сессия по задаче |
| Telegram | всё | сессия по чату Telegram |
| Название, сжатие | всё | название и сводку восстанавливаем перед записью |

**Сделано (2026-11-17):** все вызовы `getLanguageModel` идут через обёртку с сессией: чат (ответ, название, сжатие, картинка, запись памяти), задача (`task-<id>`: запуск и правка), чат Telegram; напоминание и сводка карточки — своя сессия на вызов. Модели решений памяти (`experimental_evaluate`: порог, связи, типы) получают состояние, замаскированное `maskStrings` в сессии чата; их ответы — да/нет или выбор, восстанавливать нечего. Структурный ответ (`Output.object`) восстанавливается с JSON-экранированием. Проверено тестами обёртки; сквозного теста «12 вызовов с заглушкой» пока нет.

Готово, когда: в тесте с заглушкой провайдера ни один из 12 вызовов не отправляет исходное значение из набора `ru-smoke`.

### З4. Запись «что ушло»

**Сделано (2026-11-17), миграция `0068_model_payloads`:** таблица `model_payloads`, одна строка на сообщение (`ModelPayload` в `@metobe/contracts/chat`): у вопроса — текст, как ушёл в модель; у ответа — шаги: что модель написала в тул и что получила, её текст до восстановления; метки с типом и значением (для «показать оригинал»). Обёртка сообщает замаскированный запрос и ответ модели до восстановления, `payloadRecorder` (`packages/core/src/model-payloads.ts`) собирает их и сохраняет после сообщений чата; продолжение после подтверждений дописывает шаги. Пока только чат; срок хранения — с З6.

- Таблица `model_payloads` (или поле в `metadata` сообщения — **Проверить** размер): `message_id`, `step`, замаскированные куски этого шага (сообщение, результаты тулов, ответ до восстановления), список меток с типом. Только новое в этом шаге, без всей истории.
- Значения не дублируем: «показать оригинал» берёт их из ответа шлюза, сохранённого вместе с записью, той же видимости, что и сам чат (**Допущение**).
- Срок хранения — из настроек, по умолчанию как у чата.

### З5. «Что увидела модель» у каждого сообщения (P31, выбрано 2026-11-17: «на месте»)

- У каждого сообщения человека, шага с тулом и ответа — свой значок: щит с числом скрытых значений, в строке действий под сообщением рядом с «Копировать». Где ничего не скрыто, значка нет. На компьютере он виден при наведении, как остальные действия (решено владельцем 2026-11-17); на телефоне — всегда.
- Нажатие меняет текст на месте на версию модели, повторное возвращает исходный. Каждый значок показывает только свою часть обмена:
  - сообщение человека — как оно ушло в модель;
  - шаг с тулом — что модель отправила в тул и что получила обратно;
  - ответ — как модель его написала, до восстановления значений.
- Метки — чипы в цвете своего типа (имя, телефон, почта, документ, адрес, счёт, дата рождения), одни и те же в ленте, шагах, поле ввода и настройках (`apps/web/lib/label-tone.ts`, решено владельцем 2026-11-17); наведение на метку показывает исходное значение.
- Память, которую Metobe ставит перед сообщением (`<memory>`), в пузыре не показывается: при нажатом щите в строке действий появляется «Память к сообщению», память открывается всплывающим окном. Щит считает только скрытое в словах человека. Ничто под сообщением не меняет высоту: лента прижата к низу, любая новая строка сдвинула бы её.
- Локальный источник — значок сервера «Не покидало сервер», без переключения.
- У шага «Обдумал» значка нет: рассуждения модели шлюз не хранит.
- Во время потока строка «Восстанавливаю данные» вместо обычной, пока шлюз держит хвост.
- Сухие подписи (`feedback_plain-copy`): «Скрыто 4 значения», «Не отправлено: защита данных недоступна».

### З6. Раздел настроек «Защита данных» (админ, P31, принят как в прототипе 2026-11-17)

- Включено / выключено; адрес службы и её состояние (как у источников).
- Где применять: чат, задачи, Telegram, память, служебные вызовы — по отдельности.
- Что делать с каждым типом: скрывать / оставлять / не отправлять запрос. По умолчанию организации оставляем (так в PII Guard; **Допущение**).
- Локальные источники: не маскировать (по умолчанию) / маскировать тоже.
- Режим: быстрый (правила + NER) / с проверкой моделью (`escalate`, медленнее и платно).
- Срок хранения записей «что ушло».
- Песочница: вставить текст — увидеть замаскированный, чипы и что осталось открытым.

Хранение — `system_settings.policies`, как `web-settings.ts`. Миграция — если записи З4 пойдут отдельной таблицей.

### З7. Поле ввода: что получит модель (P31, выбрано 2026-11-17: «над текстом»)

Решено владельцем: не просто подсказка, а кликабельный предпросмотр.

- Пока человек печатает, в строке поля значок-щит с числом скрытого (запрос к шлюзу с задержкой после ввода, в той же сессии чата — метки совпадут с теми, что уйдут). Текст в поле не подчёркиваем.
- По нажатию над текстом внутри поля раскрывается «Так получит модель»: сообщение с метками-чипами, кнопка «Свернуть». Вложения — отдельной строкой «уйдёт без маскирования».
- Служба недоступна — значок предупреждения, по нажатию «Не отправлено: защита данных недоступна»; отправка неактивна.
- Для локальной модели — «Не покидает сервер», без маскирования.
- Нужен метод форка «замаскировать без записи» (dry run): тот же результат, что при отправке, но хранилище сессии не меняется, если сообщение не отправят (**Проверить**: детерминированный HMAC даёт те же метки, остаётся не засорять реестр людей).

### З8. Качество

- Утечки на наших текстах: прогнать набор `ru-smoke`, проверочную часть 901–902 и выгрузку ответов тулов через middleware, а не через `pii-guard eval`.
- Падежи и перенос меток в аргументы тулов на моделях Metobe (Muse Ember, модели чата), не только на Haiku, как в замере форка. Цена заранее.

## 5. Что уже понятно о рисках

- Русская NER на текстах, которые писали не мы, не проверена (см. отчёт о ru-v1): нужен набор живых сообщений до включения по умолчанию.
- ru-v1 немного ухудшила испанский, французский, нидерландский и мальтийский; в образе ru-s34 (смесь всех языков и наш чатовый корпус).
- Одна служба в памяти: при росте до нескольких реплик нужна привязка сессии к реплике.
- Картинки и файлы шлюз не маскирует.

## 6. Решения владельца (2026-11-16)

1. **D46 — вариант Б:** middleware в Metobe, шлюз как служба маскирования.
2. Шлюз недоступен — запрос во внешнюю модель не отправляется.
3. «Что увидела модель» видит каждый у своих ответов.
4. Картинки и файлы уходят как есть, с пометкой у сообщения и в поле ввода.
5. Память маскируется так же, как чат.
6. В поле ввода — кликабельный предпросмотр того, что получит модель (З7), а не подсказка.
7. P31 (2026-11-17): в ленте — значок у каждого сообщения, шага и ответа, текст меняется на версию модели на месте; в поле ввода — версия модели раскрывается над текстом; раздел настроек — как в прототипе.
