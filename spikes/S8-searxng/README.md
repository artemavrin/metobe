# S8. SearXNG для `web_search`

Проверено 2026-09-28: `searxng/searxng:latest` (2026.9.x), Docker Desktop на macOS, домашний IP, один инстанс, без своего индекса.

## Стенд

`searxng/settings.yml` — второй раунд: JSON включён, лимитер выключен (сервис внутренний, не публичный), google и yahoo включены сверх умолчаний, приостановка движков — минуты вместо суток, исходящий трафик — через SOCKS5-прокси с логином.

```sh
docker network create s8
docker run -d --name socks --network s8 -e PROXY_USER=user -e PROXY_PASSWORD=pass serjs/go-socks5-proxy
docker run -d --name searxng --network s8 -p 127.0.0.1:8888:8080 -v "$PWD/searxng:/etc/searxng" searxng/searxng:latest
node probe.mjs              # десять вопросов, ru и en
node load.mjs out.jsonl 180 # вопрос в секунду, три минуты
node burst.mjs out.jsonl 15 # темп чата: три вопроса подряд раз в 20 с, пять минут
```

## Результат

**Качество по-русски — хорошее.** Десять вопросов (курс ЦБ, налоговый вычет, Next.js 16, REST API Битрикс24, погода; и столько же по-английски) — у всех 20–42 результата, наверху первоисточники: cbr.ru, nalog.gov.ru, nextjs.org, apidocs.bitrix24.ru, gismeteo, документация PostgreSQL. 0,6–3 с на вопрос.

**Под постоянной нагрузкой настройки по умолчанию умирают за две минуты.** Вопрос в секунду:

```
  0–90 с   почти всё с результатами — но держит один google cse:
           brave «Suspended: too many requests», duckduckgo — CAPTCHA, потом «access denied»
 90–120 с  google cse тоже «too many requests» → приостановлен
120–270 с  0 результатов: заблокированы все движки
```

Капчи начинаются рано: duckduckgo — после ~5 вопросов подряд, brave — после ~10 за 20 с, google cse — после ~100 за две минуты. Блок на стороне поисковиков держится дольше 15 минут. А SearXNG по умолчанию сам выключает движок: после капчи — на сутки, после «too many requests» — на час.

**В темпе чата с тремя движками — выживает.** Три вопроса подряд раз в 20 с, пять минут, google + yahoo + brave, приостановка — минуты: 45 из 45 с результатами, медиана 0,8–1 с. Brave периодически уходит в «too many requests» и возвращается; duckduckgo и google cse так и не вернулись с первого прогона.

**Движки по одному (русский вопрос):** google — 10, yahoo — 7, mwmbl — 36, но нерелевантно; bing — пусто без ошибки; qwant — CAPTCHA; yandex — «parsing error»; mojeek, startpage, presearch в этой версии нет.

**Прокси.** `outgoing.proxies` с `socks5h://user:pass@…` работает: прокси видит соединения, результаты приходят. Первый вопрос через прокси — холодный (таймаут 3 с у всех движков), дальше как напрямую. Упавший прокси SearXNG честно отдаёт как `proxy error` у каждого движка.

## Ответы

1. **JSON** — `search.formats: [html, json]`, иначе 403.
2. **Движки:** google, yahoo, brave, duckduckgo, google cse, wikipedia. Чем больше движков, тем реже каждый видит наш IP.
3. **Приостановка — минуты** (`search.suspended_times`), а не сутки: иначе одна плотная серия запросов гасит поиск на час.
4. **Нагрузку держим сами:** кеш одинаковых вопросов, не больше двух одновременных запросов к SearXNG. Для чата этого хватает; для агентов по расписанию и больших команд — прокси с разными IP (`outgoing.proxies` крутит список по кругу) или платный бэкенд.
5. **Так делают и другие:** Open WebUI (SearXNG или встроенный DDGS), LibreChat (поиск → скрейпер → реранкер), Perplexica (SearXNG + реранк эмбеддингами), домашние пайплайны (SearXNG + кеш поиска на час и страниц на сутки + fetch каскадом). Своего индекса ни у кого нет, «локальный поиск» — это метапоиск на своём сервере плюс чтение страниц у себя.
