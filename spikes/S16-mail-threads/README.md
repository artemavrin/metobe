# S16 — письмо и ответ без текста (Г3.1)

Можно ли связать отправленное письмо с ответом только по конвертам и заголовкам, без тела письма. Только чтение,
ящики владельца на dev, без модели и без расхода. Скрипт — `threads.ts`; конверты собирает `envelopesVia` в
`packages/core/src/mailboxes.ts` (он же пойдёт в рабочий сбор).

```sh
cd apps/cli && DAYS=365 PAIRS=/tmp/pairs.tsv npx tsx --conditions=react-server --env-file=../../.env \
  ../../spikes/S16-mail-threads/threads.ts
```

В вывод — только счётчики. Пары «письмо — ответ» для проверки руками пишутся в локальный файл `PAIRS` (там темы и
адреса — он не уходит с машины).

## Что из этого следует

1. **Заголовки надёжны.** Где ответ есть, `In-Reply-To`/`References` и «тот же адресат + та же тема» ни разу не
   разошлись (23 из 23). Только по теме — 2 пары, их надо посмотреть руками (`PAIRS`, `how = subject`).
2. **Ответы лежат не только во «Входящих».** В Mail.ru за год в корзине 744 письма: прочитанный и удалённый ответ —
   всё равно ответ. Читаются все папки, кроме черновиков, спама и «Помеченных» Gmail; у Gmail — и «Вся почта», повторы
   по `Message-ID` убираются.
3. **Ящик, куда не отвечают.** В Mail.ru адресаты ни разу не писали в этот ящик за год, и писем, на которые человек
   отвечал, в нём нет: переписка идёт через другой адрес. Без поправки Г3.1 показал бы 14 ложных «нет ответа».
   Поправка без текста: ждать ответа только от тех, кто хоть раз писал в этот ящик.
4. **«Человек написал последним»** отличимо без текста: письмо с `In-Reply-To` — ответ; ждать на него ответа не нужно
   (7 + 17 писем). Вопрос в конце такого ответа без текста не виден — это Г3.2.
5. **Проверка «95 % из 100 пар руками» на этих ящиках невыполнима:** связанных пар за год 25. Заголовочные связи
   (23) сверены с темой автоматически; ручная проверка — 2 пары по теме и живая проверка списка владельцем.

## Правило для Г3.1

Отправленное ждёт ответа, если: начинает цепочку (нет `In-Reply-To`); получателей не больше трёх; хотя бы один —
адрес карточки, и он писал в этот ящик раньше; нет входящего (кроме автоответов и рассылок), которое ссылается на
его `Message-ID` в `In-Reply-To`/`References`; нет входящего от получателя с той же темой (без «Re:», «Fwd:») позже.
